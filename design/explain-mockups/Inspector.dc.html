Why this pane, unchanged
A plan node is already field-and-value shaped: descriptor is a string map, outputs is symbol → type, and details and estimates are flat — which is what this pane renders today. Same groups, same field/value split, same hover copy button, and NaN lands on the italic grey already used for a null.
So selecting a node in any of the plan views feeds the pane that is already there, and the whole node-detail problem costs a breadcrumb and a close button.
Open question: the pane is currently driven by a table Selection. Feeding it from a plan node means widening that contract, or giving the pane a second source.
